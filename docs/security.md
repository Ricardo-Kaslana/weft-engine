# 安全与资源限制

## 信任模型

Weft 只执行应用自有或明确可信的脚本。受限 Runtime 用于减少失误和资源失控，不承诺安全执行恶意第三方 JavaScript。规范化不是通用 HTML 安全清洗器。

## 能力暴露

- 默认不安装任何 JS 能力，只有策略显式启用的命名空间可见。
- 桥接只接受受限可序列化值，并限制消息深度、字节数和队列长度。
- 每次调用校验会话、能力、方法、参数 Schema 和序列号。
- 不建立可让任意脚本调用宿主方法的通用 MethodChannel。
- 会话句柄不是唯一鉴权手段，撤销和销毁后必须立即失效。

## 网络安全

网络请求由 Dart 代理。实现时必须校验规范化后的 scheme、host、port 和路径；每次重定向重新校验。默认仅允许显式配置的 HTTP(S) 来源，不允许 `file:`、`content:`、`javascript:`、用户信息凭据和自动携带宿主 Cookie。

还应考虑 DNS 解析到私有、回环或链路本地地址的风险，并限制连接数、超时、请求体、响应体和解压后大小。应用注入的认证信息不应作为可读取值暴露给 JS。

## 执行预算

预算至少包含 JS 堆、原生栈、墙钟时间、微任务批次和桥接队列。网络等异步操作另有取消令牌和独立 deadline，不能通过等待宿主任务绕过执行预算。

JS 内存上限不等于 Flutter 总内存上限。文档、字符串、图片解码、Fragment 和 Picture 缓存需要独立预算和监控。

## 超限与恢复

1. 停止调度新任务并拒绝后续调用。
2. 中断执行或取消异步操作。
3. 保留最后一个已提交的 UI 快照。
4. 销毁异常 Context/Runtime，不复用其全局对象。
5. 上报结构化诊断，并记录最后处理的命令序列。
6. 恢复时创建新 Context，注入 Dart 权威状态；不自动重放网络等副作用。

## 图片资源安全

图片由宿主的 `WeftImageResolver` 解析，引擎不根据 `src` 自行发起请求。规范化器移除 `javascript:`、`vbscript:` 和 `data:` 图片地址，但宿主仍需执行 URL 白名单、来源认证、响应大小和解码尺寸限制。

图片解码计入独立内存预算。当前 `ImageInfo` 在节点移除、文档替换和渲染表面销毁时释放；跨页共享的资源由 Flutter `ImageCache` 和宿主策略管理。远程图片重定向必须重新校验目标来源，不得因为规范化器保留了 `https` 就默认信任。

## 内容安全边界

不可信第三方脚本始终拒绝执行。对不可信 HTML 的渲染安全性需要在独立威胁模型和经过验证的清洗流程下评估，不能仅凭本项目的规范化器作出保证。

复杂内容通过 `SupportReport` 进入宿主回退。回退到 WebView 不代表内容自动可信，其脚本与网络策略由宿主单独管理。
