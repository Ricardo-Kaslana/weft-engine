# ADR 0011：图片由宿主解析，Float 使用共享排除区

- 状态：已接受
- 日期：2026-10-25

## 背景

内容型页面需要图片和文字环绕图片。若引擎直接把 `src` 交给 `NetworkImage`，会把网络权限、重定向、认证、尺寸和缓存策略藏进渲染内核，也无法满足“受控资源”的定位。若把每个 `img` 映射为独立 Widget，又会破坏单一渲染表面并让 Float 难以跨段落工作。

## 决策

### 图片资源

- 布局引擎只接收 `Map<NodeId, ui.Image>`，自身不执行 I/O。
- `WeftImageResolver` 由宿主实现，接收文档 ID、节点 ID、`src` 和 `alt`，返回 `ImageProvider` 或 `null`。
- `RenderWeftSurface` 负责按节点解析图片、监听 `ImageStream`、在解码完成后使布局失效，并在节点移除和表面销毁时移除监听、释放 `ImageInfo`。
- 未解析或加载失败的图片按 `alt` 文本参与行内布局，不显示伪图片，也不自动回退 WebView。
- 规范化器移除 `javascript:`、`vbscript:` 和 `data:` 图片地址，但宿主仍负责 URL 白名单和解码预算。

### 图片盒

- 图片是块级替换元素：支持 HTML `width/height`、CSS `width/min-width/max-width`、`box-sizing`、padding 和边框。
- 只给宽度时按固有比例计算高度；宽度被约束时重新计算高度。
- 非浮动图片在段落中会结束当前行内流并作为块级替换盒放置。行内基线混排留待后续实现。

### Float

- `_FloatContext` 在块级格式化上下文内共享，保存带外边距的排除矩形。
- 每个行盒按当前 `y` 查询左右可用边界；可用宽度不足时下移到最近浮动底部。
- 同一侧浮动顺序堆叠；左右浮动宽度之和不超过内容宽度时可以并排。
- `clear` 将后续块级元素的边框盒推到对应浮动底部。
- 浮动不增加普通父级盒高，但浮动底部计入文档滚动高度，避免被裁剪。
- Float 内容使用逐行文本布局：每行单独测量、生成 `TextPainter` 和链接矩形；无浮动文档继续使用整段布局，避免改变已验收路径。

## 后果

资源安全边界清晰：引擎不隐式访问网络，宿主可复用 Flutter 图片缓存和自有鉴权。图片和 Float 共享同一套盒模型、`NodeId` 和绘制命令，后续表格和 BFC 可以复用 `_FloatContext` 的行框查询。

已知边界：

- 只支持图片 Float；其他元素的 `float` 仍按普通块处理。
- 浮动图片必须是块级容器的直接子元素；嵌套在行内元素中的浮动图片当前不参与布局。
- 逐行分行只覆盖“存在浮动排除区”的文本；长浮动段落会多次测量剩余文本，性能需要基准测试。
- 尚未实现 BFC、浮动与表格/行内格式化上下文的完整交互，以及 `clear` 的 margin 合并细节。
