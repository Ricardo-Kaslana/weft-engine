# ADR 0036：按已测块索引直接物化懒布局窗口

- 状态：已接受；Android JNY-AL10 profile 已验收
- 日期：2026-10-28

## 背景

ADR 0031 限制了每帧新测量的块数，但同快照换窗仍重走整个前缀和未测后缀。美化 HTML 又因 body 直属空白文本退回 full；仅跳过空白的试验使 JNY-AL10 滚动 p95 恶化到 140ms，已回滚（device-matrix §4.3）。因此不能把放宽准入当作优化。

## 决策

1. 在 `lazy_layout.part.dart` 中维护单所有者窗口状态。首次按原始 body 子节点序号生成元素条目，预计算相邻 margin 折叠、列表标记和末端 margin；后续换窗复用这些条目，不重新扫描 body。
2. 同快照且宽度、textScaler、图片、断行规则、renderer 集匹配时，复用准入结论及已测状态。快照变化仍做公共前缀比较；几何输入变化重建状态。计算样式与逻辑文本索引继续遵守 ADR 0031 的快照缓存规则。
3. 已测块按文档顺序保存在只读视图中；区间树的内部节点保存最小顶边与最大底边，叶子覆盖块流区间及真实 paintBounds。查询最终用原区间精确过滤，不能按不单调的 top 简单二分。窗口外旧资源释放，进入窗口的块才重建 TextPainter。
4. Float 排除区按测量顺序保存，每块记录进入时的排除区长度。重新物化恢复该前缀，保持 Float/clear 与原布局一致。body 背景与边框仍由外层 `layoutBlock` 按本次 extent 生成，不混入块缓存。
5. 后缀估算保存固定高度与 margin 总量、各标签剩余数量、最近 16 个真实高度样本。每个块仅在首次进入精确前缀时更新统计；重新物化不重新采样，也不改变估算 extent。测完后后缀直接归零，避免浮点扣减残差污染精确尺寸。
6. 未测区域仍按每 pass 至多 32 个新块推进；不声称首次冷跳能精确 O(log N) 定位。负 margin 的后缀最小推进量和向上绘制偏移共同提供保守停机边界；偏移包含 Float 自身的负上边距及子树负纵向 margin，避免只看下一块 top 而漏掉后来回到窗口的内容。
7. Surface 与引擎共用窗口判定，并按元素条目数量而非原始文本节点数量判断完成。`correctBy` 不触发滚动监听，WeftView 校正后显式同步真实 pixels；只有有效 extent 变化触发校正，保留 generation、用户滚动位置与 full 升级守卫。
8. 完成窗口化后，才允许 body 中 `white-space: normal` 下纯 ASCII 格式化空白不进入块流；不改规范化快照、NodeId 或原始分块序号。NBSP、真实正文及预格式化文本不放宽；复杂 Float、选区与 Semantics 的 full 路径不变。
9. 图片请求的树扫描按快照缓存，但不可用资源仍按原逻辑重试。绘制与命中共用的节点到顶层序号映射通过弱关联按快照缓存，避免布局之外仍逐帧遍历全树。

## 所有权与复杂度

窗口状态和 commands 一并转移，来源结果失去 incrementalCache，即使该窗口没有任何绘制命令也不能再次作为来源。dispose 同样使缓存失效。缓存的 blocks 是只读视图，不是可跨后续转移保存的历史快照。

首个快照允许 O(N) 建条目与索引容量；正常块流的热态只查询区间树、处理进出窗口块和新增前缀，不复制全部 metrics。重叠绘制区间或大量历史 Float 可能退化，仍不承诺病态文档的最坏情况对数复杂度；超高块、表内行与图片解码资源没有细粒度虚拟化。

新增计数 `debugVisitedBlockCount`、`debugEstimatedBlockCount`、`debugEligibilityVisitCount` 与 `debugLazyCorrectionCount` 用于守护固定成本及校正稳定性。结构测试要求 1000 段格式化文档的热态换窗只访问窗口规模的条目，估算与准入扫描为零。

## 桌面画像

运行 `flutter test tool/scroll_frame_benchmark_test.dart --no-pub --reporter expanded`，Windows，360px × 800px；300/1000 个普通段落，同一生成器仅改变空字符串或换行的拼接方式。记录实际 body 节点数：300/599、1000/1999，避免把 §4.3 的历史 601/901 元素口径混入本次数据。

下表为完全测量后顶/底往返 20 轮（40 次）直接 `layoutViewport` 调用的 p95，单位 ms：

| 段落 | 紧凑：改前 → 改后 | 换行：改前 → 改后 |
|---|---|---|
| 300 | 0.802 → 0.739 | 32.277 → 0.597 |
| 1000 | 1.372 → 0.667 | 85.350 → 0.490 |

改后四组均为 lazy，每次热态重建/持有 4 块；1000 段换行文档冷深跳分 32 pass，最终画像最慢 4.142ms。首屏 API 耗时由 78.666ms 全量变为 10.079ms（1000 段换行）。紧凑 1000 段首屏从 4.361ms 增为 12.507ms，反映首次索引准备成本及采样噪声，不能只报告热态收益。

这些是单次宿主画像，不是 FrameTiming，也不是 Android 门禁；旧版 WeftView 对已 full 的换行文档滚动不重排，上表不能当作其真实滚动帧耗时对比。最终 pump 画像 p95 为 3.067 → 1.922ms；中途一次为 3.856ms，包含测试框架及并行任务的调度噪声，不据此宣称设备改善。

## 实际应用交互

临时 Flutter Web 宿主加载真实 `WeftLabApp`，并提供 901 元素（1801 个 body 子节点）的格式化长文。Edge CDP 通过鼠标滚轮、点击和选区手势驱动，不启用 Semantics 查找元素；复查截图与结构记录保存在本地 `build/adr0036-evidence/recheck.png`、`recheck.json`。探针已停止并移出工作区，临时 workspace 配置与锁文件未留下差异。

Lab 脚本计数达到 2，图片与滚动正常。长文首屏仅物化 14 块；滚动到 prefix=55 时新排 7 块，访问 26 条目。冷跳测至末尾后回顶仅访问 28 条目、估算更新为 0；异步导航落到第 270 节。链接不关闭 lazy，选择按契约升级 full，剪贴板读回 `Selectable`；静止时布局身份稳定，复查无控制台异常。

冷 Bottom 仍有短暂空白后恢复，这是未知前缀分帧测量的已知边界，不能宣称零空白。浏览器 Web debug 的 FrameTiming 已分列 build/raster，但含软件 GPU、调试与动画成本，不作为 Android 预算证据。

## 验证边界

- 覆盖格式化文档预算与计数、热态 extent 不漂移、负 margin/显式高度溢出/body chrome、宽度与缩放失效、流式追加、Float 往返、命令所有权、异步锚点取消及 selection/Semantics full。
- 完整 format/analyze/verify/像素黄金及既有浏览器几何门禁必须通过，不更新容差或盲目覆盖参考。
- JNY-AL10（Android 10，profile，仅 arm64）复测：901 元素/1801 body 子节点格式化文档。`am start -W` 冷启动 606/635/670ms，中位 635ms；滚动 20s（1196–1201 帧）combined p95 25.5–26.0ms、p99 ≈26.5ms、最大 33.96–44.82ms、0 帧 >50ms，始终 lazy 且每次仅新排 4–5 块；冷深跳 12.05/14.80ms，滚动后深跳 33.37/37.12ms，最高 37.12ms；内存增量 +9.4～10.0MB。四项设备标准全部通过。
- 严格 60fps 的 combined p95 ≤16.7ms 未达成，瓶颈在 raster（p95 ≈17.2ms、p50 combined 14.6–23.6ms），不是排版扫描；后续若追求 60fps 应先画像光栅/合成，而不是继续压缩 layout。
- 历史 ~313ms 尖峰未复现；本次全程无 >50ms 帧。冷深跳跨度校正 10 次并在 31 帧内收敛，`fullReason=null`；异步锚点返回 true 且保持 lazy。冷跳逐帧测量期间仍有已记录的短暂空白，未做像素级零空白断言。
- iOS 仍因缺少 macOS 环境暂缓。
