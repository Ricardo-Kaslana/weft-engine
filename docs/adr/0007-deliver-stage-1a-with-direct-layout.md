# ADR 0007：以直接布局和 TextPainter 交付阶段 1A

- 状态：已接受
- 日期：2026-10-25

## 背景

Float、表格、跨段选择和增量失效都依赖稳定的文档、CSS 层叠和基础文本绘制。在缺少真实内容管线时直接搭建完整 Fragment、分块缓存和虚拟化，会固化未经使用验证的抽象。

## 决策

阶段 1A 先实现受控 HTML/CSS 规范化、结构化选择器、计算样式、Block/Inline 叠放和真实绘制。行内内容按块构建跨样式 `TextPaint`，由 Flutter `TextPainter` 完成换行和字形绘制，再输出扁平绘制命令。

当前不引入独立盒树、`ui.Picture` 分块缓存、视口虚拟化和内部滚动容器；`WeftView` 使用外部滚动视图。列表标记独立绘制，不进入正文文本。

## 后果

该方案以较小实现风险验证了内容管线、视觉层级、CJK 字体和基本长文档行为，并为后续测试提供了可运行产物。代价是：

- 每次布局为全量计算，尚未满足阶段 3 的长文档性能门禁。
- `TextPainter` 控制单段换行，尚不能按 Float 的动态行宽进行逐行布局。
- 没有 Fragment 命中索引，因此链接交互、选择和语义不能提前实现。
- 外部滚动和全量命令会增加内存与绘制成本。

进入 Float 或阶段 3 前，必须先引入 Fragment/行盒模型、文本索引和分块缓存，并通过浮动黄金测试与性能数据验证。不得在现有直接布局上继续堆叠复杂定位能力。
