# ADR 0047：「样式与状态跨快照」家族画像

- 状态：已接受
- 日期：2026-10-31

## 背景

ADR 0043 画像选定并落地了三个方向（0044 文本索引增量、0045 逐行 probe 窗口化、0046 后缀平移）后，plain 宿主四种流式形态进入 91–95% saving 档，但每轮仍剩 O(document) 成分；lazy 宿主的流式轮更是每轮固定重付全文档工作。handoff 指定的下一步是把「样式与状态跨快照」家族按画像另案，枚举六项：走查样式解析 S、lazy 准入走查、估算后缀重建、lazy 轮 textIndex 回退、k=0 头部插入索引条目平移、跨快照行级缓存。

实现前探索钉死的机制事实（本切片只画像，`lib/src/` 零改动）：

- 样式解析唯一漏斗是 `styleFor`（`styleCache` 按元素身份键控），每个流式新快照清空 → 100% miss；resolver 纯函数、零 memoization，单次成本随规则数增长。已复用轮对每个顶层块在复用检查**之前**解析一次样式（`_layoutChildren` 循环顶部 `styleFor` → 之后 `_reuseTopLevelBlock`）。
- lazy 准入走查 `_supportsLazyLayout` 每新快照全树访问并把**每个元素**的样式解析进 `styleCache`（`debugEligibilityVisitCount` 计数）；估算状态 `_prepareLazyState` 每新快照全量重建（逐子 `styleFor` + `_minimumPaintOffset` 递归下降 + ctor 两个 O(children) 循环 + 段树 O(children) 分配），估算不持久化、无后缀增量路径。
- `_incrementalTextIndex` 的参与门要求 `previousCache.blocks.length == previousChildren`——lazy 缓存只持测量窗口，恒不满足 → lazy 流式轮每轮全量 `WeftTextIndex.build`。
- k=0 头部插入（复用映射空前缀）→ 索引全量重建，0046 已记录为有界成本另案。
- plain Float 文档不播种缓存，流式轮即冷全量（0045 后剩余为逐行模型线性常数）。

## 画像方法

`tool/incremental_profile_test.dart` 新增第四实验 **E4**（`_profileStyleStateFamily`）与 E1 补形：

- **E4a**——`_styleResolveTopLevel`（只解析 body + 顶层块，即已复用轮走查的解析形状）对照 `_styleResolveAll`（全元素，即回退轮/文本索引的解析形状），测跨快照样式采用的收益上界。
- **E4b**——lazy 流式轮差分分解：U_lazy（新快照 `layoutViewport` 轮，付准入 + 估算重建 + 全量索引 + diff + 种子）对照 F_lazy（同快照轮，状态整体转移、零准入零估算零索引，`_relayoutLazyMs` 断言 `debugEligibilityVisitCount` 地板为 0）；textIndex T 与样式全量 S 经公共/同包入口直测；残差 = U − F − T − S（估算走查 + diff + 种子 + 交错噪声），打印 identityCoverage 自检。
- **E4d**——样式表规模敏感性：N ∈ {8, 64, 256} 条命中类规则的文章，测全量样式耗时与每 resolve µs。
- **E4e**——float-plain 轮残差：round − S − T = 走查本身（逐行工作），即跨快照行级缓存的收益上界。
- **E1 补形**——head-insert plain 升到 base 1000；lazy 宿主补 tail-growth / mid-edit / head-insert 三形态（base 300），验证 lazy 轮成本与变化位置无关。

E4c（k=0 份额）读 E4b 直测的 T 与 E1 的形态中位数，不设独立测量。

测量纪律：与 ADR 0043 相同——桌面 Stopwatch 只做相对比较，不当真机帧耗时（真机 ≈4× 放大，handoff 红线）；本轮开发机后台负载偏高（同一 E4 两轮绝对值差 ~1.4×），故下表绝对值给出两轮区间、份额与结构计数（eligibility/estimated/reused 为确定性计数，逐轮稳定）取独立验证值；历史对比引用 0043–0046 轮记录时注明该波动。

## 数据

| n | 元素数 | 全量解析 S（ms） | 顶层解析（ms） | 顶层/全量 |
|---|---|---|---|---|
| 300 | 931 | 2.95–3.28 | 0.75–0.85 | 25–26% |
| 1000 | 3101 | 1.99–2.40 | 0.55–0.59 | 23–30% |
| 2000 | 6201 | 3.45–5.31 | 1.02–1.28 | 24–30% |

已复用轮走查只需顶层解析（每轮 ~N+1 次 resolve），约为全量样式 passes 的 1/4——跨快照样式采用的收益上界即该列。

### E4b lazy 流式轮分解（两轮区间）

| n | U_lazy（ms） | F_lazy（ms） | T 全量索引（ms） | S 准入样式（ms） | 残差（ms） |
|---|---|---|---|---|---|
| 300 | 3.3–5.5 | 0.06–0.14 | 1.8–2.5 | 0.45–0.93 | 1.0–1.9 |
| 1000 | 11.5–14.6 | 0.03–0.05 | 7.3–8.3 | 1.6–2.6 | 2.6–3.6 |
| 2000 | 30.8–42.4 | 0.04–0.06 | 15.3–16.2 | 3.7–5.1 | 11.9–21.1 |

- 结构计数（确定性）：eligibility = 全元素数（901/3001/6001，每轮重付准入）、estimated = 全子数（300/1000/2000，每轮重建估算）。
- F_lazy ≈ 0.1ms：同快照轮把 `_LazyLayoutState` 整体转移，**lazy 流式轮 97–99% 的成本都是本家族工作**。
- 份额（跨轮稳定）：T = 38–63%（最大单项）、S = 12–18%、残差（估算走查 + diff + 种子 + 交错噪声）= 其余；残差在 n=2000 超线性增长（两轮 identityCoverage 50–62%），与估算走查/分配交错噪声混在一起，按家族整体消除处理。
- 真机 4× 投影：lazy 流式轮 ≈ 13–22ms@300、123–170ms@2000——**所有规模都超 8ms 帧预算**，是引擎现存最贵的流式路径。

### E1 lazy 形态不敏感性（base 300，独立轮）

| 形态 | lazy 轮（ms） | plain 轮（ms）对照 |
|---|---|---|
| tail-append | 5.8 | 22.8* |
| tail-growth | 5.0 | 5.6 |
| mid-edit | 5.6 | 4.2 |
| head-insert | 4.8（reused=0） | 4.5 |

lazy 四形态同一档（4.8–5.8ms，与 0043 记录的 5.2–5.6 一致）——变化位置无关，O(doc)；plain 各形态已分化且更小。*tail-append plain 本轮受后台负载扰动偏大（0046 记录 3.3ms），仅列作对照。

### E4d 样式表规模敏感性（两轮区间，301 元素）

| 规则数 | 全量样式（ms） | 每 resolve µs |
|---|---|---|
| 8 | 2.2–3.1 | 7.4–10.4 |
| 64 | 5.0–7.5 | 16.5–24.9 |
| 256 | 17.0–29.5 | 56.6–98.0 |

每 resolve 成本随规则数陡增（8 → 256 条约 7–9×，超线性）：真实 CMS 样式表（百条级规则）会把每次 resolve 放大一个量级——1000 块 × 56µs ≈ 56ms 的样式单项。样式缓存的收益随样式表规模放大。

### E4e float-plain 轮残差（331 块）

round = 259–468ms（两轮），S = 0.5ms、T = 1.5–2.0ms → **走查残差 ≈ 99%**（逐行 probe + 行 painter 的线性常数，E3 同源）。跨快照行级缓存的收益上界是整个残差，但失效键（宽度/样式/浮动槽状态）机制面大（0045 已拒绝并留案）。

### E4c k=0 头部插入索引份额

头部插入 plain 轮的索引为确定性全量重建（`_incrementalTextIndex` 的 k=0 门），成本 = T = 1.8–2.5 / 7.3–8.3 / 15.3–16.2 ms（E4b 直测）。E1 的 head-insert 与 mid-edit 中位数差（300: +0.3ms、1000: +1.2ms）低于 T——两形态的轮成本都被平移克隆与走查主导，索引差额在后台负载噪声（±3ms）以内，k=0 机会按直测 T 计。

## 结论

1. **lazy 流式轮是引擎现存最贵的流式路径**：U−F = 3.3–42ms（host），97–99% 是每快照重付的家族工作；真机 4× 后所有规模超帧预算。三大件 = 全量索引 T（38–63%）+ 准入样式 S（12–18%）+ 估算走查残差。
2. plain 宿主已复用轮的剩余 O(doc) 成分 = 走查顶层样式（0.55–1.28ms）+ 后缀克隆 + 地板走查（1.6–7.0ms@1000–2000）；样式单项可用跨快照采用消除约 1/4 全量解析的量。
3. 样式表规模敏感性（E4d）使样式缓存的价值随真实样式表大小放大，且与宿主无关。
4. k=0 索引平移是有界机会（= T），头部插入 plain 轮现由克隆/走查主导。
5. 行级缓存的收益上界极大（E4e 99% 残差）但机制面大、仅 Float 文档受益，且 Float-lazy 宿主已流式良好（E3: 2.4–5.1ms）——继续留案。

## 决策

**下一方向 = lazy 流式轮 O(change) 化（分三步走，可按数据中途收束）**：

1. **(a) lazy 轮文本索引增量参与**——放宽 `_incrementalTextIndex` 的 `blocks.length == previousChildren` 门：索引条目是（内容 + 样式表签名）的纯函数，与几何测量无关；diff 前缀已证 `_sameNode` + 样式表签名相等 + body 壳相等时，前缀 checkpoint 对齐即可复用条目（`checkpointCount == previousChildren` 保留）。单一机制、消最大单项（38–63%）。
2. **(b) 准入与估算跨快照持久化**——diff 已证不变的块区间沿用上一轮的准入结论与逐子估算（gap/minimumPaintOffset/marker 挂到缓存块或持久状态），只重建变化区后缀；消灭 S 与残差主体。（ADR 0049 修订：已交付——机制为 `_LazyChild` 前缀采用 + 后缀准入验证，边界三值 pendingMargin/leading/orderedItem 零歧义恢复。）
   2b. **①(c) lazy 走查后缀采用**（视 (a)(b) 后数据）。（ADR 0050 修订：0049 数据降级缓办——滚动轮剩余 6.94ms@2000 中种子 append 池仅 ~1–1.7ms 而机制最重，留案。）
3. **(c) lazy 走查后缀采用**（视 (a)(b) 后数据）——0046 平移复用在 lazy 路径的对应物，先论证估算/段树失效面。

第二方向 = **plain 走查样式跨快照采用**（diff 已证子树相等 + 样式表签名相等 + body 相等守卫 → 从上一轮 styleCache 按旧→新元素映射采用顶层样式；收益随样式表规模放大，E4d）。（ADR 0050 修订：已交付——前缀正扫 + 后缀尾逆扫成对种子化，E4f 同机 A/B 8 条规则 −27%、256 条 −60%，复用轮与样式表规模脱钩。）第三方向 = **k=0 头部插入的索引条目平移**（有界 T，0046 备选清单原样）。行级缓存继续留案，E4e 记为收益上界。

## 备选与拒绝原因

- **先做样式采用（方向②先行）**：机制最轻，但对 lazy 轮无效（准入在 diff 之前跑，样式采用的时机在后）；lazy 轮的绝对成本与超预算幅度远大于 plain 剩余份额，故 ① 先行、② 随后（② 的 plain 收益不因顺序损失）。
- **行级缓存**：收益上界最大（99% 残差）但仅 Float 文档受益、失效键横跨宽度/样式/浮动槽状态，0045 已论证机制面大；Float-lazy 已达标，Float-plain 属无缓存路径的整体重排问题，另案。
- **把残差按估算走查精确归因**：需把私有 `_prepareLazyState` 拆解测量或加引擎计时点，违反本切片「零引擎改动」边界；残差与交错噪声混同，家族整体消除的决策不依赖精确归因。
- **复跑全套 E0/E1/E3 作为基线**：本轮后台负载使绝对值波动 ~1.4×，E0 基线沿用 0043–0046 记录；本 ADR 只新增 E4 与 E1 补形的独立轮数据。

## 后果

- 画像工具新增 E4 实验与 `_styleResolveTopLevel`/`_relayoutLazyMs`/`_styledArticleHtml` 助手、E1 lazy 三形态与 head-insert@1000；`lib/src/` 零改动，551 项测试不变，向量与像素黄金零 diff。
- 已知限制：桌面绝对值受后台负载影响（两轮 ~1.4× 波动记录在案），份额与结构计数稳定；真机帧耗时仍以 device-matrix profile 流程为准。
- E4b 的 F_lazy 断言把「同快照轮零准入」钉进画像契约，后续改动若破坏 lazy 状态转移会被画像捕获。
