# ADR 0032：阶段 1–3 验收证据与重定界

- 状态：已接受
- 日期：2026-10-27

## 背景

开发计划（development-plan.md）的阶段 1B/2/3 各留有一批"仍需完成"条目。其中多数已在后续 ADR 中交付但未回写计划；少数按实现后的证据需要正式重定界。本 ADR 记录补齐的证据与两处重定界，作为计划文档状态落账的依据。

## 交付的证据

### 内容完整性（阶段 1/2：无丢失、无重叠、无越界、显式诊断）

- `conformance_corpus_test.dart` 对全部语料用例新增三类结构断言：每个非空白文本节点必须存活到逻辑文本索引（无静默丢失）；全部绘制命令边界必须落在文档范围内（无越界）；两两文本命令矩形不得相交（无重叠，行盒贴边不计）。
- 新增 `product_description` 与 `help_doc` 两个代表性语料用例（商品描述与帮助文档形态：图片 alt 回退、列表、规格表、引用、命令行块、有序步骤）。
- `layout_robustness_test.dart` 新增敌意输入端到端扫描：`script`、嵌套表格、未知标签、`javascript:` 图片源、注入属性五类输入都必须产出显式诊断；可渲染者照常布局，不可渲染者必须给出回退级问题。
- 发现并登记一处真实浏览器一致行为：`table_cols` 的声明列宽过约束使表格超出容器约 1px，Chromium 参考同样如此；语料门禁增加按用例的 `maxOverflowX` 容差（默认 0.5px，该用例 1.5px）并注明原因，未放宽其他用例。

### 选择与复制规模化（阶段 3）

- `text_selection_test.dart` 新增 10 万字符文档（850 段，混排 CJK、emoji 代理对与拉丁文本）随机跨段选择：40 次种子化随机选择断言复制文本长度等于全局区间长度、无孤立代理、矩形在文档范围内；手势路径经真实字形点解析锚点同样代理安全。选区字形墨迹盒（emoji 回退字体、全角标点）可超出排版步进数像素，绘制时被表面裁剪，断言按此登记容差。
- 新增选区在流式追加后保留（同 id 前缀不变，锚点继续解析）与在删除编辑后安全清除（`selectionRects` 为空、`selectionText` 为 null）的测试。

### 缓存与晚解码（阶段 2/3）

- `lazy_layout_test.dart` 新增多轮滚动往返测试：分块 Picture 缓存、物化命令与增量缓存按文档规模有界，不随滚动轮次线性增长。
- `image_layout_test.dart` 新增晚解码 Float 等价测试：图片解码前按 alt 回退布局，解码后接续布局与"一开始就有图"的全新布局逐命令一致。

### 性能记录（阶段 1/3）

- 新增 `tool/widget_baseline_benchmark_test.dart`：与"功能等价标签→Widget"管线（package:html 解析 + 富文本 span、列表标记、空白折叠、每块一个 Widget + 首帧布局）对比 article300 首次解析与布局。交错采样 10 次取中位/最小：引擎 91.7ms（最小 76.0ms），Widget 106.1ms（最小 90.4ms）——首次解析与布局核心引擎快 14%–16%，未达 40% 目标（见重定界）。
- 新增 `tool/scroll_frame_benchmark_test.dart`：300 段懒布局文档自顶向下再返回的逐帧计时（166 帧），debug 模式 median 2.5ms / p95 4.8ms / p99 13.3ms，低于 16.7/33.4ms 目标；测试环境计时含框架开销，参考设备数据仍以 weft_lab 为准。本机 Flutter 版本不支持 `flutter test --release`。

## 重定界一：跨引擎像素验收（阶段 1B）

原条目要求"固定 CJK 测试字体并增加中文像素基线，或明确把跨引擎像素目标调整为结构几何门禁"。选择后者：

- 仓库无的可分发 CJK 像素字体（Noto 类 OFL 字体以 MB 计，与"轻量引擎"定位冲突；子集化又引入构建链复杂度），中文内容因此没有像素黄金。
- 中文正确性改由结构证据覆盖：CJK 禁则（ADR 0016）单元测试、`cjk_wrap` 语料、浏览器几何基线中的 CJK 用例、以及本 ADR 的语料结构断言（无丢失/无重叠/无越界）。
- 跨引擎像素预算维持 advisory（`box_model` 已入 1% 预算），强制回归门禁保持 Flutter 固定字体拉丁像素黄金。此口径同步写入 supported-subset.md。

## 重定界二：首次解析 40% 目标（阶段 1/3）

原条目要求"首次解析与布局核心耗时较等价 Widget 基线降低至少 40%"。实测 14%–16%，差距是结构性的：

- 布局核心两侧同被 TextPainter 支配，引擎无法比 Widget 方案更快地整形文本。
- 引擎在首次解析时额外构建选择/命中/语义所需的状态（文本索引、链接矩形、运行映射、规范化诊断），这些是 Widget 方案不提供的功能。

架构真正兑现大幅优势的是后续路径，实测（同机、同方法学）：

| 场景 | 基线对照 | 引擎路径 | 降幅 |
|---|---:|---:|---:|
| 300 段尾部追加一段 | 31.8ms | 6.7ms（ADR 0023） | 79% |
| 300 段懒首屏 | 43.6ms 全量 | 3.2ms（ADR 0025） | 93% |
| 深跳底部单帧停顿 | 124.8ms | ≤ 6.3ms/帧（ADR 0031） | 停顿消除 |

因此把该验收改为：**首次解析与布局核心耗时不高于等价 Widget 基线（实测 -14%），且增量追加与懒首屏两条路径较基线降低 ≥ 40%（实测 79%/93%）**。原 40% 数字没有放弃——它落在架构设计所服务的更新与视口路径上。

## 后果

- 阶段 1B、2、3 的验收条目全部具备证据或正式重定界，development-plan.md 状态落账。
- 阶段 4（受限 JS）不在本次范围；weft_runtime_api/weft_quickjs/weft_capabilities 的边界与 FakeRuntime 契约按原计划推进。
- 帧计时与 Widget 基线为工具级参考，接入 CI 门禁前先在本机稳定多轮，阈值规则与既有性能门禁一致（10 倍宽上限）。
