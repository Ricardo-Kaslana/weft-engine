# ADR 0008：从布局文本行盒派生链接命中区域

- 状态：已接受
- 日期：2026-10-25

## 背景

链接样式已经由 CSS 层叠实现，但不可变文档节点没有对应的 Flutter Widget 或 DOM 命中树。若为链接单独建立 Widget 包裹，会破坏单一渲染表面，并使换行、嵌套样式和文本缩放后的命中区域难以保持一致。

## 决策

行内布局在合并文本片段时携带链接元素 ID 和经过清洗的 `href`。`TextPainter` 完成排版后，引擎按显示文本中的链接范围调用 `getBoxesForSelection`，把结果转换为每行一个的 `WeftLinkRegion` 矩形。

链接命中查询位于不可变 `WeftLayoutResult`，`RenderWeftSurface` 只使用当前布局结果。公开 `WeftView.onLinkTap` 将命中交还宿主；引擎不打开 URL、不启动外部应用，也不决定 WebView 或浏览器策略。

## 后果

该方案保持单一渲染表面，命中区域与换行、对齐、字体和文本缩放自然一致。跨行链接产生多个矩形，相邻链接可独立命中。

代价是：链接矩形必须随布局重建；当前只覆盖字形行盒，不包含行间空白，触摸目标可能偏小；选择手势、悬停光标和语义尚未实现。若未来需要扩大触控区域或提供可访问链接语义，应基于同一布局数据扩展，而不是重新引入逐链接 Widget。
