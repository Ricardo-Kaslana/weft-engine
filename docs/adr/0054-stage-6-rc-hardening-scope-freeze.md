# 0054 · 阶段 6 范围冻结(0.7.0-rc.1 硬化与真实场景验收)

日期:2026-11-15 · 状态:已接受 · 阶段 6

## 背景

阶段 0–5 已完成,`0.7.0-dev.3` 已于 2026-11-02 发布到 pub.dev(8 个包);
此后 ADR 0051/0053(头部插入条目平移、字体回退与 CJK 覆盖)已在 main 落地
但尚未发布。各技术路线候选已收束:

- 60fps 光栅归因与后端 A/B 完成(B1,device-matrix §4.7):瓶颈是
  后端/驱动层全屏文本光栅,引擎侧没有免费优化空间;
- 语义增强(C0–C3)与 RTL(D1)已交付,读屏真机验收未做;
- 增量布局「样式与状态跨快照」家族(ADR 0047–0051)清单全部销账,
  剩余固定成本需要重新画像才能选择方向。

继续扩大 HTML/CSS 子集不再是主线。RC 前的真实缺口是三件事:

1. bridge 与资源边界**没有单一事实来源**:`docs/security.md`、Runtime
   契约与 QuickJS/Fake 后端测试各自描述了部分边界(bridge 消息字节数、
   JSON 深度、in-flight 队列、取消/dispose/recover 竞争),没有对账。
2. 平台与无障碍证据不全:iOS 物理设备未验(模拟器 CI 已通过),
   TalkBack/Web 读屏从未验收,语义开启的帧耗时未测。
3. 外部宿主从未用**发布包**(而非 path 依赖)跑过目标场景;公开 API、
   bridge 协议与快照契约也尚未冻结,不能以 dev 版本宣告稳定。

## 决策

### D1 · 阶段目标 = `0.7.0-rc.1` 准入,不承诺 1.0.0

本阶段把已交付的受控渲染、受限 Runtime、虚拟化与发布机制推进到候选发布
质量;不承诺 1.0.0 稳定版。四项阶段目标:

- **S6-1 安全与资源契约闭环(P0)**:对账并实现 bridge 消息字节数、
  JSON 深度、in-flight 队列、取消与 dispose/recover 竞争语义;让
  `docs/security.md`、Runtime 契约与 QuickJS/Fake 后端测试描述同一套边界。
- **S6-2 平台与可访问性验收(P0)**:iOS 物理设备 Runtime 与帧耗时验证;
  Android TalkBack 与至少一个桌面 Web 读屏组合的既有语义验收;语义开启
  时的滚动/深跳帧耗时补测。
- **S6-3 流式性能收束(P1)**:先重跑增量画像,再只选择一个数据支持的
  剩余热点做优化;strict 60fps 光栅研究不混入本阶段准入。
- **S6-4 外部试点与候选发布(P0)**:workspace 外真实宿主用发布包跑通
  CMS 文章、商品描述、帮助文档、AI 流式四类场景;冻结公开 API、bridge
  协议与快照契约后进入 RC。

### D2 · 里程碑顺序 M0→M4

- **M0 基线与范围冻结**(本 ADR + 文档同步 + 非目标确认)。若试点需要
  ADR 0053 的字体回退,可按发布清单先切 `0.7.0-dev.4`;该版本仍是 dev,
  不代表 RC 门禁已过。
- **M1 Runtime 安全补口(P0)**:QuickJS 与 Fake 后端的超限、取消、销毁
  竞争和恢复去重契约测试;实现或明确降级 bridge 消息/队列限制;网络等
  异步操作不得绕过执行预算;新增公开契约先经 ADR 审查。
- **M2 真机与无障碍(P0)**:iOS 物理设备验证加载、求值、墙钟/堆/微任务
  中断、恢复和代表场景帧耗时;TalkBack 抽查 heading 导航、live
  region/atomic、窗口化语义、RTL 播报和链接动作;证据写入 device matrix。
- **M3 性能画像与单项优化(P1)**:重跑 `tool/incremental_profile_test.dart`
  与同设备真机数据;仅当画像确认收益时,在「中部编辑后缀采用推广」与
  「剩余 lazy 估算/状态工作」中选一个方向;canonical 全量、像素黄金与
  选区/语义行为必须零差异。
- **M4 试点与 RC 收敛(P0)**:外部宿主用发布包(非 path 依赖)完成四类
  场景;覆盖 JS 全关、单能力关闭、WebView 回退、快照旧版本读取与回滚;
  S0/S1 清零后执行 release checklist、pub dry-run 与 published consumer
  smoke,最后才打 `0.7.0-rc.1` tag。

### D3 · 阶段门禁

- **正确性**:`tool/check.sh`、规范化 22 向量、API 文档覆盖与像素黄金全绿;
  新增行为同时覆盖正常、边界和失败路径。
- **安全**:bridge 与网络资源不得无界增长;取消/恢复/销毁后不得发生重复
  网络副作用;发布前 50,000 轮 fuzz 无未解决崩溃。
- **平台**:Android 既有 A 档标准不回退(滚动 p95 ≤33ms、无可感知停顿、
  10 轮内存增量 <20MB);iOS 物理设备证据齐全,否则发布说明必须明确
  iOS 缺口且不得宣称可用。
- **性能**:任何优化必须提供同机同文档 A/B 数据;strict 60fps 继续作为
  独立光栅研究,不作为本阶段阻断条件。
- **发布**:公开 API、快照 JSON、bridge 协议、能力策略和回退路径的兼容
  组合完整记录;无 S0/S1,S2 必须有负责人与关闭条件。

### D4 · 明确非目标(范围冻结)

- 不扩展到完整浏览器、Flexbox、嵌套表格、任意元素 Float、完整 ARIA 或
  不可信第三方 JS 沙箱。
- 不为追性能删除正确性测试、放宽像素预算或绕过格式化上下文;不以一次
  手工计时替代画像。
- 不把选择工具条、竖排、行内完整 BiDi、表内虚拟化和超高块虚拟化作为
  RC 阻断项。

### D5 · 版本路径

`0.7.0-dev.4`(若切割)只承载 main 上已验收的功能(如 ADR 0053 字体
回退),供外部试点尽早消费;RC 准入只能走 M4 门禁,dev 版本不得被宣传
为稳定或 RC。

## 备选与取舍

- **直接承诺 1.0.0 稳定版**:被否——iOS 物理设备与读屏验收未执行,
  strict 60fps 未达成;版本号不应宣告能力边界之外的东西。
- **把 strict 60fps 纳入 RC 门禁**:被否——B1 已证明 raster 瓶颈在
  后端/驱动层,引擎侧无免费空间;保持独立研究,避免 RC 被不可控的外部
  因素阻断。
- **先切 dev.4 再冻结范围**:被否——范围先冻结,否则 dev 版本会变成
  移动中的目标;ADR 0053 已在 main,试点需要时按清单切割即可。
- **把性能优化并列为主目标**:降级为 P1 单项——家族优化(0043–0051)
  已把 plain 四形态推到 91–97%、lazy 滚动轮 −77–84%,剩余成本需要
  新画像才能证明收益,不能预设方向。

## 后续

- M1 启动时先产出 `docs/security.md` 与 Runtime 契约/测试的差异对账清单,
  再逐项实现或降级。
- M2 依赖设备排期,建议与 M1 并行预约(iOS 真机、Android 测试机、
  桌面 Web 读屏组合)。
- `0.7.0-dev.4` 是否切割由外部试点需求决定,不阻塞 M1。
