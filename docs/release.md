# 发布与回退

## 发布通道

内部 Alpha 用于静态布局，Beta 用于复杂排版和长文档，RC 用于 Runtime、安全和真机验证，稳定版要求所有门禁通过。版本日期不能替代质量条件。

## 版本兼容

公开 Dart API、能力 Schema、规范化策略和 QuickJS 原生库可能独立演进。发布清单必须记录它们的兼容组合，以及 Flutter/Dart 最低版本和平台构建环境。自 `0.7.0-dev.1` 起 Flutter 依赖包与示例要求 Flutter `>=3.35.5`（ADR 0038）；纯 Dart 包仍保持 Dart `>=3.5.0`。

稳定版后公开包采用语义化版本。破坏性接口、行为或规范化变化需要迁移说明；预发布版本允许通过 ADR 调整，但必须在 Changelog 标明。

## 发布产物

- Dart/Flutter 包和锁定的依赖解析。
- 对应平台原生库、符号和第三方许可清单。
- 示例应用、功能矩阵和支持度说明。
- 单元、契约、黄金、模糊、安全和真机性能报告。
- API 文档、Changelog、迁移和回退指南。

## 独立开关

宿主必须能够关闭全部 JS、关闭单个能力包，或按诊断把指定内容路由到回退渲染器。关闭 JS 不应影响静态内容呈现。

## 回退顺序

1. 关闭问题能力或 JS。
2. 回退到上一兼容规范化策略。
3. 对问题内容启用 WebView/专用库。
4. 必要时回退引擎和原生库到同一兼容版本组合。

恢复 Runtime 或重试内容时，不自动重放已提交的网络副作用。回滚后验证静态渲染、能力撤销和缓存清理。

## 发布检查

发布前确认无 S0/S1、CI 与真机报告齐全、黄金差异已审查、原生库可复现构建、文档与代码一致、回退示例可运行，并完成一次关闭 JS 和版本回滚演练。
