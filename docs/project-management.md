# 项目管理

## 角色与责任

- 项目负责人：范围、优先级、业务样例和跨团队协调。
- 架构负责人：模块边界、公开 API、ADR 和阶段技术验收。
- 布局负责人：文档、排版、选择、绘制和性能。
- Runtime 负责人：QuickJS、桥接、网络安全和资源恢复。
- QA/性能负责人：独立门禁、浏览器参考、真机数据与发布报告。
- 发布/文档负责人：构建、版本兼容、示例、文档和回退清单。

布局核心、桥接、安全策略和原生构建修改需要模块负责人参与审查。

## Backlog 层级

使用 `Epic → Feature → Task → Test Evidence` 组织任务。每个 Ready 任务必须有输入输出、依赖、负责人、参考行为、验收、失败路径和回退定义。

P0 为核心正确性、崩溃、安全和静默错误；P1 为里程碑所需性能、语义、恢复、文档与扩展；P2 为额外 CSS、Flexbox 和其他后续能力。

## 工作流

`Backlog → Ready → In Progress → Review → Verify → Done`

每人同时只推进一个主要任务。进度只统计已满足完成定义的验收项，不以代码行数或主观百分比计算。

完成定义见 `CONTRIBUTING.md`，至少包括审查、测试、性能无未解释回退、资源释放、文档和 ADR。

## 阶段门禁

- G1：规范、静态黄金和性能基线。
- G2：Float/CJK/表格正确性与缓存失效。
- G3：长文档选择、帧性能和内存稳定性。
- G4：Runtime 中断、越权、恢复和副作用去重。
- G5：真机矩阵、文档、回退、构建和回滚。

S0/S1 缺陷不允许以条件放行方式进入下一阶段。

## 风险登记

每项风险记录触发信号、影响、负责人、缓解措施、回退路径和状态。重点跟踪：

| 风险 | 触发信号 | 首选处理 |
|---|---|---|
| Float 与浏览器偏差 | 黄金差异或重叠用例增加 | 冻结新 CSS，修正格式化上下文 |
| 增量失效错误 | 宽度或图片变化后残留旧布局 | 扩大到格式化上下文重排 |
| 长文档选择漂移 | 随机复制或更新重映射失败 | 阻断门禁，保持逻辑模型单一事实源 |
| QuickJS 中断不可靠 | 超限测试超时或宿主卡死 | 关闭 JS，重新评估后端和线程边界 |
| 性能目标失败 | P95 或内存连续回退 | 画像定位，不以降低正确性换性能 |
| 子集膨胀 | 新需求绕过 RFC 或回退策略 | 产品、架构、QA 联合复核范围 |

## 沟通节奏

定期进行阻塞清理和范围风险评审；每阶段以可运行 Demo 和证据进行门禁审查。S0/S1 完成后形成无责复盘，并把根因转化为自动化防回归用例。
