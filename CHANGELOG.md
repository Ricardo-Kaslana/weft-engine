# Changelog

## Unreleased

- Font fallback for CJK and other missing glyphs (ADR 0053). Computed styles carried a single `fontFamily`, `font-family` lists lost every candidate after the first, and hosts had no way to hand the engine a CJK face, so Chinese text always painted as tofu boxes. `font-family` now parses as the ordered candidate list CSS defines — the first named family is the primary, the rest become fallbacks, and generic keywords only participate when they lead the list (keeping the previous `monospace`/`serif` mapping, and fixing `font-family: Georgia, serif` to actually pick Georgia). Hosts can declare extra families through the new `fontFamilyFallback` parameter on `WeftLayoutEngine.layout()`/`layoutViewport()`, `WeftSurface` and `WeftView`; those are appended after the families the author already named and are inherited by descendants. Because the resolved list is baked into every style and every shaped `TextPainter`, a changed list drops `previous` and runs a cold layout rather than teaching each reuse path about the extra key. Tests 587 -> 596 (new `font_fallback_test.dart`); the three pixel goldens are unchanged.

- First pub.dev publication of all eight packages at `0.7.0-dev.3` (2026-11-02). Verified with `tool/consumer_smoke.dart --mode published`: a plain `weft: ^0.7.0-dev.3` dependency resolves and renders outside the workspace. Docs updated accordingly: the README install section leads with the hosted one-liner (Git + overrides stays as the fallback), and the release runbook records the publishing gotchas hit in practice — a read-only `PUB_HOSTED_URL` mirror must be overridden to `https://pub.dev` for uploads, `flutter pub` rejects `-C`, and pub.dev rate-limits new package creation.

## 0.7.0-dev.1 (2026-10-31)

- Added the MIT license.

- Repository quality gates: capability and test documentation now matches the current implementation (587 tests, 22 normalization vectors, table support and semantic virtualization), and CI pins Flutter 3.35.5 on both jobs, uses read-only permissions with cancellation and timeouts, and fails before tests when the QuickJS native library cannot load.

- Index entry shift for k=0 head inserts (ADR 0051): a streaming round whose change sits at the head — insert, deletion or head rewrite, where pre-order node ids shift and the forward diff proves nothing — no longer rebuilds the text index in full. The backward diff (ADR 0046) already proves the trailing body children shape-identical and maps old->new node ids; a new `WeftTextIndex.buildFromSuffix` walks the fresh head children, then adopts the previous entries for the carried children with their `globalStart` shifted past the head walk and their node ids re-mapped. Adoption starts at the first carried child whose seam walk state (hardBreaks, blockBreakPending, lastEmittedBreak, atLeadingEdge) matches the previous build's checkpoint flag for flag; a mismatch is re-walked fresh — the stream's leading edge is the one state that cannot be adopted across, because the previous build stripped its first entry's leading whitespace — and walking every carried child degrades to exactly the canonical full build. The trailing-trim restore mirrors ADR 0048, and the head walk mirrors the body's block-break initialization so the head checkpoints stay faithful for the next round's prefix adoption. The head-insert round keeps every seam child's cost instead of T (the full-index build): same-machine stash A/B for E1 head-insert rounds, 2.11 -> 1.16-1.38 ms at 300 blocks and 7.82 -> 3.02-3.09 ms at 1000 (-60%), with the per-round `entries=` profile field pinning 1500/5000 adopted entries. `debugReusedEntryCount` now counts both adoption directions. Tests 579 -> 587.

- Cross-snapshot style adoption for plain reused rounds (ADR 0050): the decision block seeds the walk's style cache with the previous round's resolved styles for every diff-mapped top-level child — a continuous forward scan over the prefix plus a reverse scan over the suffix tail — so the per-child `styleFor` hits instead of re-matching every selector each round. Computed style is a pure function of content plus stylesheet, all proven equal by the diff gates (subtree equality, stylesheet signature, body shell, tagRenderers identity), no code compares style object identities, and a lazy previous cache that lacks prefix entries degrades gracefully by stopping at the first child. The stylesheet-size amplification is decoupled from reused rounds: same-machine A/B for mid-edit rounds at 300 blocks, 2.61 -> 1.91 ms with 8 stylesheet rules (-27%) and 29.14 -> 11.66 ms with 256 rules (-60%), adopted count 299/299 vs 0/0; the remaining large-stylesheet round cost is the diff plus the ADR 0046 suffix clone. Direction 1(c) (wholesale lazy-state adoption) is demoted by the ADR 0049 data — the remaining seed-append pool is ~1-1.7 ms at 2000 blocks against the heaviest mechanism — and stays on the shelf. A new `debugAdoptedStyleCount` counter and an E4f stylesheet-size experiment pin engagement. Tests 572 -> 579.

- Lazy admission and estimate prefix adoption across snapshots (ADR 0049): the lazy decision block now runs the block diff first, and a new incremental admission adopts the previous pass's verdict for the diff-proven raw prefix, verifying only the changed suffix (the shared visitor is extracted; a negative verdict with a non-empty prefix re-runs the diff in plain mode so the suffix translation survives, since lazy-mode maps would feed unmaterialized blocks into a plain walk). The estimate walk adopts the previous pass's per-child `_LazyChild` state for the proven prefix — element re-bound to the new snapshot, style/gap/marker/minimum-paint-offset carried verbatim — and recovers the boundary margin-collapse state (pendingMargin, leading, ordered-item counter) exactly, so the resolver and the minimum-paint-offset descent never see adopted children and the hard style-cache assertions become structurally unreachable for them. `debugEligibilityVisitCount` now counts only the suffix visits. Same-machine before/after for scrolled tail-append rounds: 2.01 -> 1.57 / 6.02 -> 3.88 / 12.76 -> 6.94 ms (-22/-36/-46%); admission visits drop 931 -> 111 at 300 blocks; family cumulative from the ADR 0047 baseline: 30.8-42.4 -> 6.9 ms at 2000 blocks (-77-84%), putting the 300-block scrolled round under the 8 ms device budget at 4x. New test file covers adopted tables, body-level list markers, float-imagery exclusions, boundary margin collapse, ineligible suffixes, the plain re-run and chained rounds. Tests 561 -> 572.

- Incremental text index for lazy streaming rounds (ADR 0048): the index's incremental build no longer requires the previous cache to cover the whole body — entries are a pure function of subtree content plus the stylesheet signature, never of geometry, so a partially measured lazy window's diff-proven prefix reuses entries and only the suffix is re-walked. Two latent ADR 0044 defects are fixed along the way: the stream-tail trim/drop restore now also applies when the previous document's final entry sits inside a partial prefix (reachable today by plain mid-document edits after trailing silent children — entries, text and length silently diverged from the canonical build), and the incremental build carries its prefix checkpoints so its output again holds one checkpoint per body child (chained rounds previously alternated incremental/full, halving the benefit). New E4b scrolled shape: tail-append rounds at a scrolled viewport 6.3 -> 2.7 / 14.7 -> 7.1 / 48.2 -> 15.3 ms (-57/-52/-68%); fresh-viewport shapes stay window-bounded and unchanged, head inserts (k=0) keep the full build, and interleaved body-level whitespace only shortens the raw prefix (never correctness). WeftTextIndex gains a debugReusedEntryCount getter. Tests 551 -> 561.

- Style & state cross-snapshot family profiling (ADR 0047): the fourth profile experiment decomposes what a streaming round still pays after ADR 0044-0046. A lazy streaming round is 97-99% per-snapshot family work (U-floor = 3.3-42 ms host across 300-2000 blocks while the same-snapshot floor is ~0.1 ms): the full text-index rebuild is 38-63% (the incremental gate requires the previous cache to cover the whole body, which partial lazy windows never do), the admission walk re-resolves every element's style (12-18%), and the estimate/state rebuild plus diff plus seed accounts for the rest. Walk-style resolution for reused plain rounds is only the top-level ~quarter of a full style pass (0.55-1.28 ms at 1000-2000 blocks), per-resolve cost grows ~7-9x from 8 to 256 stylesheet rules (large CMS stylesheets amplify every resolve), and a plain float round is 99% walk/line residual (the recorded upper bound for the deferred cross-snapshot line cache). E1 adds lazy tail-growth/mid-edit/head-insert shapes (rounds are shape-insensitive, O(document)) and head-insert at 1000 blocks. Decision: lazy streaming rounds go O(change) first (text-index gate relax, then admission/estimate persistence, then walk suffix adoption as data warrants), then cross-snapshot style adoption for plain reused rounds, then the k=0 head-insert index entry shift; the line cache stays deferred. Engine sources unchanged; tests stay at 551.

- Suffix translation across streaming snapshots (ADR 0046): the block diff now also scans backward past the changed region, and shape-identical trailing blocks are reused shifted by one shared vertical delta instead of being re-measured — mid-document edits, deletions and head inserts (the weft_live update shape) join tail append in the 91-95% savings tier. Node ids are pre-order positions, so any node-count change in the middle shifts every suffix id: the backward scan compares shape (ids ignored), collects the old-to-new mapping, and the shifted clones re-map every command, run, box, link and tag-region id so hits, selection, semantics and chunks all read the new snapshot's ids. Float exclusions from the prefix or middle must not reach the shifted region (the guard falls back to fresh measurement), body-level `li` stops the scan (marker numbers are baked into cached commands), and the ownership chain matches the existing reuse path: the previous result's dispose skips the originals and each painter is disposed exactly once by this result's clones. Plain path only — float documents never seed a plain cache and lazy passes keep their windowed behavior. Mid-document edit 21.6 -> 2.3 ms at 300 blocks, head insert 40.9 -> 2.4 ms, mid-edit at 1000 blocks 66.7 -> 9.9 ms. Tests 542 -> 551.

- Windowed float line-break probing (ADR 0045): the per-line path's probe painter no longer shapes the whole remaining text once per line (quadratic — a 8000-character paragraph took 764 ms). The probe now covers about two lines' worth of characters and doubles until the break lands strictly inside the window; because fitting is prefix-monotone and the break keeps a 16-unit margin from the window edge, the windowed break equals the full-text break, and inputs that defeat the window fall back to the exact full-text probe. Run lookup (`runSpecs`/`_spanForRange`) binary-searches a shared cursor prefix instead of rescanning every run per line. The 8000-character paragraph drops to 11.1 ms (−98.5%, quadratic → linear), `floatWrap` 6–9 → 4.8 ms, float-article streaming rounds 328–430 → 222–243 ms. Line breaks are pinned unchanged by the float Chrome-geometry, pixel-golden, kinsoku, RTL and inline-image suites plus 5 new coverage/kinsoku/monotonicity/window-growth tests. Switching non-overlapping paragraphs to the whole-paragraph path remains rejected (documented path differences would change output). Tests 537 → 542.

- Incremental text index across streaming snapshots (ADR 0044): a streaming snapshot no longer rebuilds `WeftTextIndex` from scratch — the layout engine's block-diff prefix now proves which leading top-level blocks are unchanged, and the index reuses those entries verbatim (including their global offsets), restoring the previous build's trimmed stream tail before re-trimming at the new end. Both builds share one walker, and every top-level body child records a resume checkpoint, so the incremental result is equivalent by construction and pinned entry-for-entry against canonical full rebuilds in 14 new tests (tail append, whitespace/`<br>`/hidden-block boundaries, mid-document edits, chained rounds, head-insert and partial-lazy-prefix fallbacks, stylesheet changes, seam-spanning selections). Lazy partial windows, head inserts and stylesheet changes keep the full build. A new-snapshot round at 2000 blocks drops from 19.5–23.1 ms to 8.8 ms (−60%) and `appendArticle300Incremental` measures 7.1 → 5.8–6.0 ms back-to-back; the remaining round cost is dominated by the walk's style resolution. Tests 523 → 537.

- Incremental layout profiling (ADR 0043): a third manual benchmark, `tool/incremental_profile_test.dart`, decomposes the streaming-update round (snapshot diff is nearly free at ≤1.7 ms even for 2200 blocks; the text-index rebuild dominates at 56–81% and internally re-resolves every element outside the style cache), prices the update shapes (tail append and tail growth save 84–93% over cold, mid-document edit 44–60%, head insert — the weft_live shape — 0%), and prices the float path (plain hosts never seed an incremental cache for float documents and pay the per-line path's ~30× per-paragraph constant plus in-paragraph O(n²), 764 ms for one 8000-char paragraph, while lazy hosts already stream image-float documents through the ADR 0036 window at parity with float-free articles). Direction decision: text-index increment next (cross-snapshot prefix reuse with an entry-for-entry equality guard), then per-line path reuse, then suffix translation; float-checkpoint-as-reuse is demoted. Engine sources are unchanged; tests stay at 523.

- RTL base direction and language attributes (ADR 0042): the normalizer keeps `dir` (`rtl`/`ltr`/`auto`, invalid values dropped with `html.dir.invalid`) and `lang` on every element. Blocks resolve a base direction — `dir` attribute (with `auto` resolved through a first-strong directional character scan) or the new CSS `direction` property — that flows into the text painters, so `textAlign: start` right-aligns RTL paragraphs, the per-line float path probes line ends on the correct visual edge, list indents and markers mirror to the right (UA `padding-inline-start` semantics), and caret rectangles hug the leading glyph edge. `lang` becomes the TextPainter locale (BCP-47 parsed) affecting line breaking and font fallback; documents without `lang` keep the engine default `Locale('zh')` byte-identically. Semantics leaves carry the block direction as their `textDirection`. A new `rtl_paragraph` conformance case pins ten direction-sensitive text edges against a fresh Chrome reference (±2px); the 21 existing normalization vectors are unchanged (new `synthetic_dir_and_lang` vector, 22 total). Complex BiDi reordering, vertical writing and box-level logical-property mirroring remain out of scope; tests 509 → 523.

- Semantic virtualization (ADR 0041): `assembleSemanticsNode` no longer upgrades a lazy layout to the full document. Screen readers now assemble windowed semantics on the live lazy result — materialized blocks exactly as before, measured-but-dematerialized blocks near the viewport (±2–3 screens) collapse into one coarse per-block leaf carrying the flattened text, and the unmeasured suffix appears as scrolling materializes it, matching how Flutter's own lazy widgets expose semantics. The lazy memory and cold-start wins survive screen-reader use, `scrollToAnchorAsync` works with semantics enabled, and cold deep jumps with a screen reader now surface the ADR 0037 settling overlay and `onLazySettlingChanged` signals instead of silently paying a synchronous full relayout. Selection, anchor-rect fallbacks, async image decoding and engine fallbacks still force the sticky full layout exactly as before. Coarse leaves announce block text only (no inline structure, markers, roles or tap targets) and re-focus when a block rematerializes to exact nodes. Layout, paint, snapshots and pixel goldens are unchanged; tests 508 → 509.

- ARIA foundation (ADR 0040): the normalizer keeps `role` (conservative mapping), `aria-hidden`, `aria-atomic` and `aria-label` on standard tags, closing the gap where the engine already read `aria-label` for custom tags while the normalizer dropped it. `role="button"/"link"` announce through `isButton`/`isLink` flags without activation actions; `role="img"/"heading"` collapse or derive header/headingLevel; `role="dialog"/"alertdialog"` become semantic containers; `role="alert"/"status"` act as implicit live regions with whole-group announcement; `presentation`/`none` suppress an element's own derived semantics while content stays announced; every other role is dropped with an `aria.role.unsupported` info diagnostic. Explicit roles override implicit semantics (`<a role="button">` loses the link flag and tap). `aria-hidden="true"` removes a subtree from the semantics tree (visuals and copy text unchanged). `aria-label` names an element: on `img` it beats `alt`, elsewhere it collapses the subtree into a single named leaf (structural table tags excluded; `<a aria-label>` keeps its tap). `aria-atomic="true"` inside a live region announces the subtree as one `liveRegion` leaf instead of per-leaf — the ADR 0039 limitation. Layout, paint, snapshots and pixel goldens are unchanged; the 21 normalization vectors stay byte-identical; tests 495 → 508.

- Accessibility/content semantics (ADR 0039): `h1..h6` now expose `SemanticsConfiguration.headingLevel`, explicit `aria-live` (`off/polite/assertive`) marks descendant leaf semantics as Flutter live regions, and `ol[start]` / `li[value]` control both visual and semantic ordered-list markers. The normalizer preserves these attributes and drops invalid values with diagnostics; the pinned lists normalization vector was regenerated (the only vector whose output changed). Documents without the new attributes keep the same tree, layout and paint output.

- Compatibility baseline (ADR 0038): all Flutter-dependent packages and examples now declare `flutter: ">=3.35.5"`, and every package moves to `0.7.0-dev.1`. `weft_engine` has used `SemanticsRole` (Flutter 3.35.5) since ADR 0030 while the pubspecs still advertised 3.22; hosts on Flutter 3.22–3.34 could resolve the package but never compile it. No runtime, layout, snapshot, bridge or golden changes; pure Dart packages keep Dart `>=3.5.0`.

- Cold deep-jump settling (ADR 0037): `WeftView.lazySettlingBuilder` lets hosts cover the viewport while budgeted lazy passes measure a deep target; `onLazySettlingChanged` and `WeftViewState.isLazySettling` report start/finish from post-frame callbacks. No layout, overscan, budget or raster changes; unconfigured views keep the existing progressive fill. `example/weft_live` wires a static skeleton and a jump-to-bottom control, and the Android device run records the overlay timing in `docs/device-matrix.md` §4.8.

- B1 backend A/B on JNY-AL10 (12 Impeller + 12 Skia ABBA rounds, profile, reconstructed 901-element probe): no reproducible raster advantage for either backend — SCROLL total p95 median 25.70 vs 24.49 ms (p=0.33), PAINT_ONLY stable raster p95 8.77 vs 9.75 ms (p=0.42); the only significant delta is SCROLL build p95 (0.38 ms lower on Skia), which does not affect the frame budget. Do not disable Impeller on this Mali class; strict 60fps remains unmet. Evidence under `build/adr0036-evidence/b1/`.

- Lazy layout now materializes measured windows from a conservative paint-bounds index (ADR 0036): admission, block-flow margins/lists and suffix estimates are cached per snapshot, while only entering/leaving blocks rebuild or release commands. Formatting whitespace between body blocks no longer disables virtualization; body text, NBSP and `white-space: pre` keep the full-layout path.

- Float exclusions are restored from the measured prefix when a block rematerializes, body chrome still follows the current estimated extent, and `correctBy` extent corrections now sync the surface to the real scroll offset instead of replaying corrections.

- Windows host profile (300/1000 paragraphs): warm `layoutViewport` p95 dropped from 1.37/85.35ms to 0.67/0.49ms for compact/newline documents; first viewport for the 1000-paragraph newline document went from 78.67ms (full) to 10.08ms (lazy). These are API timings, not device frame times.

- Verified on Huawei JNY-AL10 (Android 10, profile, 901-element formatted article): 635ms median cold start, 25.5–26.0ms combined scroll p95 with no frame above 50ms, 37.12ms max deep jump, +9.4–10.0MB memory. Strict 60fps (p95 ≤16.7ms) is not met; raster p95 ≈17.2ms dominates.

- 15 new regressions cover formatted-window budgets, negative-margin upward overflow, body chrome, invalidation, ownership transfer, async-anchor cancellation and correction convergence.

- Added `example/weft_live`, a web-target live editorial demo rendered in one Weft surface: auto-refreshed metrics and pulse chart, streaming updates, topic filters, light/dark themes, deep links, poll/clap custom tags, and end-to-end tests that tap tags through the semantics tree.
